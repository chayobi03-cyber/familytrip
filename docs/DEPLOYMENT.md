# 배포 및 운영 가이드

## 현재 배포 형태

이 프로젝트는 서버가 없는 정적 웹 앱입니다. 앱 소스는 `trips/jeonju/app/` 아래에 있으며 GitHub Pages 워크플로는 이 디렉터리의 내용만 배포 artifact로 업로드합니다. 배포된 artifact의 루트에 `index.html`, `css/`, `js/`가 포함되므로 상대 경로를 유지할 수 있습니다.

## GitHub Pages 배포 절차

1. 저장소 루트의 `.github/workflows/pages.yml`이 테스트 실행 경로 `trips/jeonju/app` 및 artifact 경로 `trips/jeonju/app`을 사용하는지 확인합니다.
2. GitHub 저장소의 **Settings → Pages**를 엽니다.
3. Build and deployment의 Source를 **GitHub Actions**로 선택합니다. 현재 연동 토큰은 Pages 사이트 생성 권한이 없어 자동 활성화가 실패했으므로 이 설정은 저장소 관리자 화면에서 직접 완료해야 합니다.
4. `main`에 푸시하거나 Actions에서 워크플로를 수동 실행합니다.
5. 테스트 및 배포 job이 모두 성공하는지 확인합니다.
6. GitHub가 표시한 Pages URL을 열고 아래 점검을 수행합니다.

> 실제 배포 URL은 GitHub Pages 설정 후 GitHub가 제공하는 값을 사용합니다. 설정하지 않은 URL을 배포 완료 주소로 안내하지 않습니다.

## 배포 후 스모크 테스트

- [ ] 앱 페이지가 HTTPS로 열림
- [ ] 콘솔에 치명적인 JavaScript 오류가 없음
- [ ] Leaflet 지도 라이브러리와 지도 타일이 로드됨
- [ ] 일정 대안과 날짜 탭이 동작함
- [ ] 일정 순서/포함 상태 편집 후 새로고침 복원 확인
- [ ] 사용자 장소 생성 후 브라우저 저장·재실행 복원
- [ ] 사진 추가 후 브라우저 재실행 시 복원
- [ ] 모바일 뷰포트에서 주요 조작 수행
- [ ] 운영시간·예약·주차가 실시간 보장되지 않는다는 점이 명확함

## 업데이트 절차

1. 변경 전 최신 `main` 상태와 이슈를 확인합니다.
2. 명세서의 관련 요구사항과 인수 테스트를 함께 갱신합니다.
3. 앱 코드는 `trips/jeonju/app/`에서 수정합니다.
4. `cd trips/jeonju/app && node tests/engine.test.js`로 엔진 테스트를 실행합니다.
5. 의미 있는 변경 단위로 커밋하고 Pages 배포 상태를 확인합니다.

## 데이터 보관 및 개인정보

- 일정과 사용자 장소 정보는 각 브라우저의 로컬 저장소에 저장됩니다.
- 사진 파일은 IndexedDB에 저장됩니다.
- 다른 기기/브라우저로 자동 이동하지 않습니다.
- 브라우저 저장 데이터를 삭제하면 일정·장소·사진을 복구하지 못할 수 있습니다.
- 공개 저장소에는 예약번호, 연락처, 실시간 위치 등 민감한 여행 세부정보를 올리지 않습니다.

## 문제 해결

### 지도가 표시되지 않음
인터넷 연결, Leaflet CDN 요청, OpenStreetMap 타일 요청 및 콘텐츠 차단 설정을 확인합니다. 지도가 없어도 일정 텍스트가 열리는지 확인합니다.

### 변경사항이 다시 열 때 사라짐
같은 브라우저/프로필인지 확인하고, 사이트 데이터 저장이 허용되어 있는지 점검합니다. 시크릿 모드나 저장소 정책에서는 데이터가 보존되지 않을 수 있습니다.

### 사진이 보이지 않음
IndexedDB 사용 가능 여부, 이미지 파일 형식/크기, 브라우저 저장 공간을 확인합니다.

### 운영정보가 잘못됨
앱은 실시간 영업/예약 확인 도구가 아닙니다. 공식 채널로 당일 운영과 예약 여부를 확인하고 사용자 메모를 갱신합니다.
