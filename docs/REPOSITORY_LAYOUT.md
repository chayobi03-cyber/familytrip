# 가족여행 플래너 — 저장소 구조 및 마이그레이션 명세

- 문서 버전: 1.0
- 기준일: 2026-10-16
- 목표 저장소 이름: `familytrip`
- 방식: 단일 모노레포
- 상태: **여행지 구조 및 공통 모듈 문서 추가 완료 / 저장소 이름 변경은 미완료**

## 1. 목적

여행지별로 저장소를 분리하지 않고 하나의 저장소에서 여행 계획, 재사용 모듈, 공통 제품 명세를 관리한다. 전주 앱을 계속 사용할 수 있도록 기존 배포 경로를 우선 보존하고 단계적으로 이동한다.

## 2. 목표 디렉터리

| 경로 | 책임 |
|---|---|
| `trips/jeonju/` | 전주 여행별 계획, 장소 목록, 여행 인수 문서 |
| `trips/taean/` | 태안 여행별 계획, 체크리스트, 현장 확인 기록 |
| `modules/` | 다른 여행에서도 재사용할 수 있는 장소/활동/체크리스트 모듈 |
| `docs/` | 제품 명세, 데이터 규약, 아키텍처, 운영·배포 문서 |
| 저장소 루트의 기존 앱 파일 | 마이그레이션 기간 동안 GitHub Pages 호환성 유지 |

## 3. 전환 원칙

1. 기존 콘텐츠를 삭제하거나 새 프로젝트로 덮어쓰지 않는다.
2. 웹 앱 경로 변경은 배포 워크플로와 테스트를 함께 변경하고 검증한 뒤 수행한다.
3. 여행지별 정보와 공통 모듈을 분리한다. 공통화 전에는 한 여행의 세부 일정에 과도하게 종속된 규칙을 모듈에 넣지 않는다.
4. 실시간 운영정보에는 출처와 확인 시각을 기록하고, 확인되지 않은 정보는 확인 완료로 표시하지 않는다.
5. 공개 저장소에는 숙소 예약번호, 연락처, 가족의 실시간 위치·이동 일정 등 개인정보·안전상 민감한 정보를 올리지 않는다.

- [ ] 링크 및 Pages URL 설정 확인

현재 연결된 GitHub 작업 도구에는 저장소 이름 변경 작업이 노출되지 않아 이 단계는 자동 실행하지 못했다. GitHub 저장소의 **Settings → General → Repository name**에서 변경해야 한다.

### Phase 3 — 앱 파일 이동 (별도 변경으로 수행)
- [ ] 앱을 `trips/jeonju/app/`로 옮길지 결정

- [ ] 링크/자산 상대경로, GitHub Pages 기본 URL, 새 여행 추가 방식 검증

**Phase 3는 이번 구조 커밋에 포함하지 않는다.** 현 워크플로는 저장소 루트 전체를 배포하므로 검증 없이 앱을 이동하면 배포가 중단될 수 있다.

## 5. 여행 데이터와 모듈 규약

- 여행 계획은 `trips/<destination>/` 아래에서 관리한다.
- 여러 여행에서 재사용 가능한 요소는 `modules/<module-name>/` 아래에 둔다.
- 모듈에는 이름, 용도, 입력/출력 데이터, 출처, 확인일, 주의사항을 포함한다.
- 계획 값과 실시간으로 검증된 값을 구분한다.
- 예약, 입장, 운영시간, 날씨, 조석 등 시간 민감 정보는 출발 전에 공식 출처로 다시 확인한다.

## 6. 완료 기준

- 전주 앱의 현재 Pages 배포 경로가 유지된다.
- 여행지별 새 자료를 독립된 경로에 추가할 수 있다.
- 공통 모듈 작성 규칙과 저장소 구조 문서가 존재한다.
- 이름 변경은 실제 GitHub 저장소 URL에서 확인한 후에만 완료로 표시한다.
